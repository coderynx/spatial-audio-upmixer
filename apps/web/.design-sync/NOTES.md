# design-sync notes — upmixer-web

Design system = `apps/web/src/components/` (ui/ primitives + forms/ fields + stems/).
Config home is `apps/web/.design-sync/`; run the converter from `apps/web`.

## Build setup (fresh clone must redo)

- **Self-symlink required**: `apps/web` IS the `upmixer-web` package but isn't
  installed in its own `node_modules`. The converter resolves `PKG_DIR =
  node_modules/upmixer-web`. Recreate: `ln -sfn .. node_modules/upmixer-web`
  (from `apps/web`). Without it, build dies with ENOENT on
  `node_modules/upmixer-web/package.json`. Gitignored (node_modules).
- **Synth-entry mode**: no library dist (it's an app). Converter synthesizes the
  entry from `src/components/**`. `cfg.srcDir = "src/components"` scopes discovery
  to the DS (bare `src` pulls in ~100 app feature components).
- **tsconfig**: `cfg.tsconfig = tsconfig.app.json` resolves the `@/*` → `./src/*`
  path alias for the esbuild bundle and ts-morph props.
- **CSS is compiled Tailwind**: `src/index.css` has raw `@tailwind` directives,
  useless as static CSS. `cfg.buildCmd` runs the Tailwind CLI → stable
  `.design-sync/compiled.css` (gitignored), which `cfg.cssEntry` points at.
  The dist hash-named css is NOT used (unreproducible).
- **Authored-preview utilities MUST be in Tailwind content**: Tailwind only
  emits classes it finds. Preview cards use utilities the app source never uses
  (e.g. `h-56`). `.design-sync/tailwind.previews.ts` extends the app config with
  `./.design-sync/previews/**/*.tsx` in `content`, and `buildCmd` uses `-c` on it.
  If a preview renders unstyled/collapsed, first suspect a utility missing from
  compiled.css — add the class somewhere the content glob sees, or rebuild css.

## Fonts

- Font stack is a deliberate SYSTEM-font stack (`-apple-system,
  BlinkMacSystemFont, "SF Pro Text", Inter, ui-sans-serif, system-ui, ...`).
  No brand font is ever bundled. `cfg.runtimeFontPrefixes = ["SF Pro","Inter"]`
  suppresses `[FONT_MISSING]` — correct: shipping a font would fight the
  OS-native intent; on the Linux render host it falls to system-ui/sans-serif
  (the designed fallback). Not a substitute decision.

## Component authoring

- **Fader / Pot / HorizontalFader** are controlled canvas-style audio controls
  with NO intrinsic height (track is `h-full`, all children absolute). A preview
  must give the control a sized parent AND pass `className="h-full"` to the
  control, or it collapses to ~0px. Real usage: `src/features/projects/MixerView.tsx`
  (Fader), `Transport.tsx`/`TimelineView.tsx` (HorizontalFader), `forms/fields.tsx` (Pot).
- Controlled components render statically at their initial `value` fine (noop or
  useState onChange).

## Component authoring gotchas (learned)

- **Radix Select closed-trigger value text**: a closed `Select` with `defaultValue`
  shows NO value text — Radix resolves the display text from the portaled
  `SelectContent` items, which are unmounted while closed. Preview `Select.tsx`
  uses `<SelectValue placeholder="…"/>` (unselected state) instead, which renders
  reliably. Don't "fix" it back to defaultValue.
- **Dialog** open state is authored (`<Dialog open>`); `cfg.overrides.Dialog` sets
  `cardMode:"single"` + a viewport so the fixed/overlay content renders in-card.
  The preview also neutralizes the default `-translate/left-1/2/top-1/2` and the
  huge `w-[min(1100px,92vw)]` via className so it sits inside the card.
- Preview cards import from `"upmixer-web"` (mapped to `window.UpmixerWeb`); lucide
  icons and app lib helpers (`@/lib/*`) bundle from source and resolve fine.

## Floor-card components (intentional, not failures)

17 subcomponents ship importable with the typographic floor card — they're pure
structural/context-bound parts shown inside their parent's authored preview:
Dialog{Trigger,Close,Portal,Overlay,Content,Header,Title,Description},
Select{Trigger,Value,Content,Item}, Tabs{List,Trigger,Content}, CardTitle,
CardDescription. Authoring them standalone is low-value (most throw outside their
parent context). The 18 meaningful top-level components all have authored previews.

## Re-sync risks (what can silently go stale)

- **Self-symlink** `node_modules/upmixer-web → ..` is gitignored — recreate on a
  fresh clone (`ln -sfn .. node_modules/upmixer-web`) or the build ENOENTs.
- **`compiled.css`** is generated by `cfg.buildCmd` (Tailwind CLI via
  `tailwind.previews.ts`) and gitignored. The driver reruns `buildCmd`, so it
  regenerates — but only if `buildCmd` still resolves. If the app renames/moves
  `tailwind.config.ts` or `src/index.css`, update `buildCmd` + `tailwind.previews.ts`.
- **Preview → app-lib coupling**: Fader/HorizontalFader/Stem previews render the
  real components, which import app helpers (`@/lib/stems`, `@/lib/meterScale`,
  `@/lib/canvasTheme`, `@/lib/fader`) bundled from source. If those move/rename,
  those previews (and the bundle) can break — rebuild and re-grade them.
- **Component discovery** is synth-entry over `src/components/**`: a NEW component
  there is auto-included as a floor card on the next sync (author a preview to
  upgrade it); a REMOVED one lands in the diff's deletePaths.
- **System-font assumption**: `runtimeFontPrefixes` suppresses SF Pro/Inter. If
  the app ever ships a real `@font-face` brand font, revisit (wire via `extraFonts`).
- Only partially exercised: dark mode (previews captured in light theme only —
  tokens are defined for both, but dark cards weren't screenshotted).
