# Mastering / stem EQ FIR filters

`master_<profile>.wav` — mono minimum-phase FIR for each mastering-bus EQ
profile (`upmixer/mastering/eq.py` `EQ_PROFILES`), 48kHz, 1023 taps.

`stem_<profile>.wav` — mono minimum-phase FIR for each per-stem EQ profile
(`upmixer/separation/stem_eq.py` `STEM_EQ_PROFILES`), 48kHz, 511 taps.

`audioEngine.ts`'s `loadFirTaps` fetches and decodes these directly, and
passes the taps into the shared Rust core's `eq_fir` parameter, which
convolves and wet/dry blends by `strength` the same way the backend's
`_apply_fir` does — the preview renders the *actual* backend-computed FIR,
not an approximation of its curve.

Generated by `scripts/build_eq_filters.py`, which calls the backend's own
`_build_fir` functions directly. The backend does not read these files back —
it keeps computing the FIR live at runtime, which is the source of truth this
script calls into; only the browser preview loads the shipped asset.
Regenerate after changing either profile table.
